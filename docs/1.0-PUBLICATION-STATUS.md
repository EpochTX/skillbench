## Why there is no `v1.0.0` tag yet

The first public npm bootstrap run reached `npm publish` only after all release checks passed, but npm returned `ENEEDAUTH`. The GitHub Actions log showed `NODE_AUTH_TOKEN` was empty. The workflow therefore skipped registry verification, tag creation, and GitHub Release creation exactly as intended.

This is an external npm-account authorization requirement, not a product-code, package-content, test, audit, or build failure.

No `v1.0.0` tag or GitHub Release should exist until `skillbench-ai@1.0.0` is publicly resolvable from npm and its registry repository metadata has been verified.

## Safe bootstrap retry

The repository Publish workflow exposes an explicit manual `workflow_dispatch` retry. It is hard-pinned to the validated release commit above and refuses a different commit for the 1.0 bootstrap.

Before running it, an npm maintainer must provide one valid publication identity:

1. add a repository Actions secret named `NPM_TOKEN` with permission to publish the first public `skillbench-ai` version, **or**
2. if the package has subsequently been bootstrapped by another authorized path, configure npm Trusted Publishing for repository `EpochTX/skillbench` and workflow `publish.yml`.

Then run the **Publish** workflow with its default `release_sha`. The workflow will:

1. check out only the validated release commit;
2. rerun the complete release gate;
3. verify whether `skillbench-ai@1.0.0` already exists and belongs to this canonical repository;
4. publish with provenance when needed;
5. verify the public registry version and repository metadata;
6. only then create `v1.0.0` pointing to the validated release commit and create the GitHub Release.

Until those registry steps complete, use SkillBench from the validated source commit rather than assuming the npm command is available.
